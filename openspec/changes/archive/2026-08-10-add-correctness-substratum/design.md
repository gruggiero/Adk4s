# Design: Correctness Substratum (schema v12)

The template's sections are Scala-shaped. This change ships bash, YAML and
markdown, so each section is answered in the terms that actually apply and
every non-applicable section carries a verdict with reasons rather than being
deleted — the change's own subject matter makes silent omission the wrong
default here.

## Package Structure

### Layers

"Package" maps to directory under `openspec/schemas/verified-scala3/`. The
binding rule is the PREREQUISITE RULE from the capability profile (declared
tool set only; no JVM, no network), which replaces the superseded
zero-dependency portability rule.

| Layer | Directory | Depends On | Must NOT invoke | Ring 2 rule |
|-------|-----------|-----------|-----------------|-------------|
| Checks (pure-ish, callable standalone) | `scanner/` | `git`, `jq`, coreutils | any harness API; any network; any JVM | A check must run identically from a shell prompt and from a hook |
| Harness integration | `hooks/` | `scanner/*` | project source; anything not in the prerequisite set | `gate.sh` holds all logic; adapters only decide *when* to ask and *where* to put the answer |
| Adapters | `hooks/adapters/` | `hooks/gate.sh` | `scanner/*` directly | An adapter contains no logic — it is configuration plus a call |
| Tests | `tests/` | everything above | project source | Tests may not require a running harness |
| Fixtures | `tests/fixtures/` | — | — | Committed; never regenerated by a test run |

The adapter rule is inherited verbatim from the existing hook documentation
(*"the adapter decides when to ask and where to put the answer; all logic stays
in `gate.sh`"*) — it is what makes adapters interchangeable, and the two new
event tiers must not erode it.

### New Directories

| Directory | Layer | Purpose |
|-----------|-------|---------|
| `tests/` | Tests | NEW — no test layout exists for the 11 tracked scripts; this change establishes it |
| `tests/fixtures/` | Fixtures | NEW — Ring 4 compatibility baselines |

## Effect Boundaries

Everything in this change performs I/O. The meaningful split is between
**decision logic** (given inputs already read, compute an answer) and
**acquisition** (read files, run subprocesses, emit output). Decision logic is
where correctness lives and where tests are cheap; the design pushes as much
into it as bash reasonably allows.

| Component | Decision logic | Acquisition |
|-----------|---------------|-------------|
| `ledger.sh` | field validation; row encoding; predicate filtering by change/spec/baseline | file append; file read |
| `chain-state.sh` | set nesting and counting; unresolved-list assembly; undetermined determination | invoking `spec-lint.sh`; invoking `ledger.sh` |
| `checkpoint.sh` | row selection by baseline; render | reading the ledger and tracker; writing the checklist |
| `gate.sh` | payload assembly; fingerprint comparison; refusal decision | invoking `chain-state.sh`; reading event JSON; writing heartbeat |

**Design consequence**: each script exposes its decision logic as a function
taking already-read input on stdin or as arguments, so bats can exercise it
without staging a repository. Acquisition is a thin outer shell. This is the
bash equivalent of "actor state transitions delegate to pure functions".

## Type Strategy — Invalid-State Prevention

Bash has no type system, so the ladder is realised through **call shape and
single-writer discipline** rather than through types. Every invariant from the
specs is placed and justified.

| Invariant | Level | Mechanism | Justification |
|-----------|-------|-----------|---------------|
| A ledger row cannot be written without command, exit status and baseline | **Good** | `ledger.sh append` takes named flags and refuses when any required flag is absent; there is no interface accepting a preformatted line | "Best" is unreachable in bash — no type can make a missing field unrepresentable. Single-writer plus named flags is the strongest available rung |
| A field value cannot corrupt row framing | **Best** | Records are JSON objects, one per line, encoded by `jq` — framing is a property of the encoder, not of caller discipline (see Decision 1) | Escaping correctness moves from hand-rolled bash into a tool whose job it is. Hand-rolled escaping is precisely where this project's existing string-surgery risk sits |
| An existing ledger row cannot be altered | **Good** | Append-only writer; no update or delete subcommand exists to invoke | Filesystem permissions could raise this, but a read-only ledger cannot be appended to by the same process; refusing at the only writer is the achievable rung |
| A stale-baseline row cannot discharge an obligation | **Good** | Baseline is a required field on every WRITE. `ledger.sh read`'s own `--baseline` is optional (several already-approved evidence-ledger.bats scenarios read across baselines on purpose — corrected at the checkpoint-from-ledger spec's Step 1 gate; this row previously claimed "there is no read path that ignores baseline", which was false the moment `--baseline` was omitted). Every CALLER that discharges an obligation from a read — `chain-state.sh`, `checkpoint.sh` — supplies it unconditionally, by its own discipline | Making it structurally impossible would require per-baseline files, which fragments the record for no gain. Enforcing it in the shared reader was considered and rejected: it would force every existing non-scoped caller to pass a dummy value for no safety benefit, since none of them discharge anything from the result |
| Undetermined evidence cannot be reported as zero discharged | **Best** | Distinct exit codes (see Decision 2): a caller cannot receive `0` for an undetermined read, because the undetermined path returns `2` and carries no counts | This is the ladder's "Bad" row inverted — silently mapping unreadable input to a valid-looking answer is the defect the whole change targets |
| A completion gate cannot deadlock a session | **Good** | Refusal state is per-turn and consumed on read | "Best" would require the harness to guarantee it; bounded refusal is what the script can enforce alone |
| A hook cannot fail a session | **Good** | Injection events exit `0` unconditionally, with every internal failure caught and reported in payload text | Inherited from the existing gate; the new blocking tier is confined to the completion event and is separately specified |

**Forbidden row check**: no invariant in this change is placed at "Bad"
(silently maps invalid input to valid behaviour). One — undetermined evidence —
is explicitly designed to make that placement unreachable.

## Refined Type Strategy

Not applicable in the template's sense: no Iron, no refined library, no
Scala. The analogous decision is **which values are validated at the boundary
versus passed through**, recorded here so it is not left implicit.

| Value | Validated | Rationale |
|-------|-----------|-----------|
| change name, spec name | yes — non-empty, no path separator | they index into ledger reads; a path separator would let a row escape its scope |
| baseline revision | yes — non-empty, matches a revision shape | the staleness rule depends on exact comparison |
| exit status | yes — an integer | a non-integer would silently compare unequal forever |
| ring identifier | yes — from a closed list | an unrecognised ring must be rejected, not recorded and later rendered as an unknown row |
| command text | no — arbitrary | it is opaque payload; JSON encoding makes its content harmless (Decision 1) |
| obligation, artifact | no — arbitrary text | human-readable references; no structural constraint |

## IDL Model Layout

No Smithy or protobuf is involved. Two **wire contracts** exist and are treated
with the same seriousness, because both cross a process boundary:

| Contract | Format | Producer | Consumer |
|----------|--------|----------|----------|
| Evidence ledger record | JSON object per line (Decision 1) | `ledger.sh append` | `chain-state.sh`, `checkpoint.sh` |
| Hook event response | JSON on stdout, existing shape | `gate.sh` | Claude Code, Devin CLI, pi adapter |

The hook response shape is **unchanged** by this design — the existing
`hookSpecificOutput.additionalContext` contract is what the harnesses already
consume, and the new tiers reuse it rather than inventing a second shape.

### Evidence ledger record

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `v` | integer | yes | record schema version; `1` for this change. Ring 4's forward-compatibility hinge |
| `ts` | string | yes | ISO-8601 UTC |
| `change` | string | yes | scoping |
| `spec` | string | yes | scoping |
| `ring` | string | yes | closed list |
| `obligation` | string | yes | free text |
| `artifact` | string | yes | free text |
| `command` | string | yes | the command executed |
| `exit` | integer | yes | its status |
| `baseline` | string | yes | revision the run applies to |

## Error Strategy

### Exit-code discipline (applies to every script in this change)

| Code | Meaning | Never used for |
|------|---------|----------------|
| `0` | ran, and found nothing wrong | an unreadable input |
| `1` | ran, and found something wrong (findings, refusal, unresolved) | a tool that could not run |
| `2` | **could not determine** — input unreadable, dependency absent, subprocess failed for a non-finding reason | anything the caller might read as a clean result |

This three-way split is the design's single most load-bearing decision after
the record format. Collapsing `2` into `1` would make "the check failed" and
"the check could not run" indistinguishable; collapsing it into `0` reproduces
the exact defect the change exists to remove. Existing scripts use a two-way
split (`0`/`1`); they are **not** retrofitted by this change, but `chain-state`
must interpret a non-finding failure of `spec-lint.sh` as undetermined rather
than as findings.

### Error propagation

| Boundary | Pattern |
|----------|---------|
| script → script | exit code plus a message on stderr; the caller distinguishes `2` before reading stdout |
| script → hook | the hook catches every failure, exits `0` for injection events, and reports the condition in payload text |
| hook → harness | the documented JSON shape; a refusal for the completion event uses the harness's documented refusal field |
| any → human | stderr, naming the file and line for parse failures |

**No swallowed errors**: a failure is either surfaced in the exit code or
rendered into the payload; it is never discarded. The existing gate's
`set -uo pipefail` (deliberately not `-e`, so a failed probe degrades rather
than aborting) is retained and extended to the new scripts.

## Compatibility Story (Ring 4)

Ring 4 **APPLIES** — the ledger is persisted, read by two other scripts, and
archived with its change, so a format change breaks stored evidence.

| Data | Format | Compatibility mechanism | Test |
|------|--------|------------------------|------|
| Evidence ledger | JSON lines, versioned by the `v` field | A reader accepts any `v` it knows; an unknown `v` is **undetermined** (exit `2`), never skipped and never treated as absent | `evidence-ledger.bats` |
| Committed fixture | JSON lines at `v=1` | A fixture written by this version is committed and re-parsed by every later run; it may never be regenerated to make a test pass | `tests/fixtures/evidence-ledger-v1.jsonl` |
| Hook response | existing JSON shape | Unchanged; asserted by the cross-format property so a future edit cannot silently alter it | `gate-payload.bats` |

**Fixture obligation**: `committed v=1 fixture → read → expected rows` and
`new row → append → read → same field values`.

The unknown-version rule deserves emphasis: the tempting behaviour is to skip
records a reader does not understand, which would make a forward-incompatible
ledger read as *partially discharged*. That is the silent-degradation shape, so
an unknown version is undetermined for the whole read.

## Pure Code (Ring 6 candidates)

Every candidate gets a verdict. These are the verdicts pulled out of the specs,
where the lint correctly flagged them as belonging here.

| Module / Function | Purpose | Ring 6? |
|-------------------|---------|---------|
| `chain-state` set nesting and counting | the fold at the centre of the change: partition requirements into bound ⊇ resolved ⊇ discharged and count them | **No — closest call in the change.** Algorithmically it qualifies: there is a fold, and inputs reduce to a triple of Booleans per requirement, which PureScala models easily. It is rejected on a different ground than the ones v10 forbids: the shipped code is **bash**, not Scala with unverifiable types. A mirror would prove that nested sets imply ordered counts — true by construction and trivial — while the actual risk, *whether the implementation produces nested sets*, is only observable by running the script. The bridge test would have to invoke bash from a Scala test to say anything about what ships. Delegated to the enumerated property "Counts never exceed the total and are monotone across clauses" and "The unresolved list and the counts agree" in `chain-state` |
| `ledger.sh` encode/decode | record framing and field recovery | **No** — serialization, not an algorithm. The round-trip law is directly covered by Ring 3's enumerated property and Ring 4's committed fixture |
| `checkpoint.sh` row selection | filter rows by change, spec and baseline, then render | **No** — a filter over parsed input with no law beyond "reported ⊆ rows at this baseline", covered directly by the enumerated properties "Every reported outcome traces to a row" and "No baseline mismatch is ever reported as current" |
| `gate.sh` fingerprint suppression | inject only when facts changed | **No** — the law is an equivalence (`injects ⟺ facts differ`) covered exactly by the enumerated property "Suppression depends only on whether facts changed". A model would restate the property, not strengthen it |
| `gate.sh` payload assembly | render text | **No** — string assembly; no decision, fold or law |
| hook event dispatch | route an event to a check by path | **No** — a lookup; totality over the path set is covered by the exhaustive enumerated property in `hook-tiers` |

**Language mismatch is stated as the reason, not hidden.** v10 rules out two
excuses — unverifiable production *types* and a Scala-version mismatch with the
Stainless frontend. Neither applies: the objection here is that the shipped
artifact is not Scala at all, so a mirror's bridge test could only reach it
through a subprocess. That is a real distinction, and if the project later
decides subprocess bridges are acceptable, `chain-state` is the one candidate
worth revisiting.

## Technical Decisions

### Decision 1: Ledger records are JSON lines, not tab-separated values

**Context**: The `evidence-ledger` spec was written before the `jq` ban was
lifted, and assumed a tab-separated format. Three of its scenarios and one of
its properties exist solely to handle separator characters appearing inside a
field — and the `command` field will routinely contain quotes, and can contain
tabs and newlines.

**Options considered**:
1. TSV with hand-rolled escaping — no dependency; matches the awk-based style
   of the existing scanners; greppable.
2. JSON lines encoded and decoded with `jq` — escaping handled by the tool;
   now permitted by the prerequisite set; still one record per line.
3. TSV with a separator assumed not to appear — rejected outright; that
   assumption is exactly the class of silent corruption this change targets.

**Decision**: **JSON lines (option 2)**. The escaping problem is not incidental
here — the field most likely to contain the separator is required in every row.
Hand-rolled escaping in bash is where this project's string-handling risk
already concentrates. Delegating framing to `jq` moves the invariant from
"Good" (caller discipline) to "Best" (impossible to express) on the type
strategy ladder, which is the only invariant in this change that reaches the
top rung.

**Consequences**:
- **The `evidence-ledger` spec must be amended** — its Concepts Introduced,
  three separator scenarios, one property and its Implementation Anchors all
  name the tab-separated format. The amendment narrows nothing and removes no
  case: the awkward-value enumeration survives intact, now covering quotes,
  newlines and non-ASCII as JSON string content. Because the spec is a
  commitment approved at the spec-lint gate, this amendment is re-linted and
  re-presented rather than applied silently.
- Records stay one-per-line, so `grep` still works for coarse filtering.
- `jq` runs once per read, not once per row.
- The `v` field makes future format migration explicit rather than inferred.

### Decision 2: Three-way exit codes, with 2 reserved for "undetermined"

**Context**: The existing scripts use `0` for clean and `1` for findings. The
`chain-state` spec requires that unreadable evidence never be reported as zero
discharged, and that requirement cannot be met with a two-way split — a caller
receiving `1` cannot tell "the lint found problems" from "the lint could not
run".

**Options considered**: a two-way split with a sentinel string on stdout;
a three-way exit code; a structured status object on stdout.

**Decision**: **three-way exit code**, `2` = undetermined. It is checkable by
every caller in the language's own idiom, cannot be missed by a caller that
forgets to parse stdout, and needs no dependency.

**Consequences**: existing scripts are **not** retrofitted — that would widen
this change into every scanner. Instead `chain-state.sh` interprets its
callees' failures: a `spec-lint.sh` exit that is not a lint finding is treated
as undetermined. This is a documented asymmetry and is worth a follow-up change
to normalise the older scripts.

### Decision 3: Decision logic is separable from acquisition in every script

**Context**: Ring 3 must exercise the interesting behaviour, and staging a full
repository per bats case is slow and fragile.

**Decision**: each script exposes its decision logic as a function over
already-read input, with acquisition confined to a thin outer shell. Tests
drive the function; a smaller number of cases drive the shell end-to-end.

**Consequences**: enables the enumerated properties to run over constructed
inputs rather than constructed repositories. Costs a discipline that bash does
not enforce, so it is a Ring 2 rule and a Ring 8 review item rather than a
guarantee.

### Decision 4: The blocking tier ships last and separately

**Context**: The existing hook documentation declines blocking hooks because a
misfiring one strands the agent, and asks for promotion on evidence.

**Decision**: `hook-tiers` is last in the implementation order, and within it
the post-edit tier lands before the completion gate. The ledger is advisory —
feeding the payload — before it becomes checkpoint-generating.

**Consequences**: the non-blocking path accrues real usage before anything can
refuse. If the payload proves wrong or noisy, that is discovered while the
worst consequence is still a wasted context block rather than a blocked turn.
